## 학습 목표

- 안전·장치·환경·graph/QoS·TF/time·Nav2·base 진단 순서를 적용한다.
- 증상별 마지막 PASS와 다음 확인 계층을 구분한다.
- 정지 불가·발열·반복 disconnect에서 즉시 STOP한다.

## 선수 조건

- PART 1~5의 환경·graph·TF·실물·Nav2 Gate

## 핵심 개념

| 증상 | 마지막으로 증명된 계층 | 다음 확인 |
| --- | --- | --- |
| SSH도 안 됨 | 전원만 확인 | IP·Wi-Fi·SBC |
| topic은 보이나 수신 0 | name·type | endpoint·QoS |
| Path 있음·cmd 없음 | Planner | Controller·local costmap |
| cmd 있음·바퀴 정지 | ROS command | OpenCR·motor·wheel |

## 준비

- 현재 장비·shell·경로·ROS 배포판을 확인한다.
- 이 Lesson에서 필요한 실제 입력이 없으면 결과를 만들지 않고 `HOLD`로 남긴다.
- 명령과 관찰을 같은 실행 회차의 증거로 연결할 저장 위치를 준비한다.

## 실행

```bash
ros2 doctor --report
ros2 topic info /cmd_vel --verbose
ros2 topic hz /cmd_vel
ros2 run tf2_ros tf2_echo map base_link
```

## 예상 결과

:::{admonition} 예상 결과의 경계
:class: expected-result
아래 항목은 원문이 제시한 판정 기준이다. 실제 장비·설치본의 출력 로그를 이 문서가 대신 만들지는 않는다.

- 증상을 첫 실패 사다리에 배치한다.
- 마지막 PASS와 첫 FAIL을 한 쌍으로 기록한다.
- 다음 확인은 첫 FAIL의 바로 아래 또는 해당 계층으로 제한한다.

## 관찰 포인트

- `/cmd_vel` 이름·type·publisher와 실제 바퀴 움직임을 분리한다.
- 무작위 parameter 튜닝보다 첫 실패 계층을 먼저 고정한다.

## PASS / HOLD / FAIL

::::{grid} 1 1 3 3
:gutter: 2
:class-container: status-gate-grid

:::{grid-item-card} ✓ PASS
:class-item: status-pass
첫 FAIL과 마지막 PASS가 증거와 함께 기록되고 수정 범위가 한 계층으로 제한된다.
:::

:::{grid-item-card} ◇ HOLD
:class-item: status-hold
증상만 있고 마지막 PASS 또는 첫 FAIL을 재현하지 못했다.
:::

:::{grid-item-card} ✕ FAIL
:class-item: status-fail
여러 계층을 동시에 조정하거나 정지 불가·발열·disconnect를 무시하고 재시도한다.
:::

## STOP 조건

:::{danger}
정지 불가·발열·반복 disconnect가 있으면 즉시 STOP하고 전원을 차단한다.
:::

## 실패·문제해결

- SSH 실패를 ROS parameter로 해결하려 함
- Path가 있으므로 Controller도 정상이라고 추정
- command 확인만으로 motor·wheel 정상 판정

첫 수정 전에 **마지막 PASS와 첫 FAIL**을 기록하고 한 번에 한 변수만 바꾼다.

## 확인 문제

**질문:** `/cmd_vel` publisher와 값이 정상인데 wheel이 움직이지 않으면 다음 계층은?

:::{dropdown} 정답 확인
:class-container: knowledge-answer
OpenCR·motor·wheel의 device·물리 계층을 확인한다. ROS command 증거가 물리 반응을 대신하지 않는다.
:::

## 실습 과제

현재 문제 하나를 첫 실패 사다리에 놓고 변경하지 않은 채 마지막 PASS·첫 FAIL·다음 확인을 세 줄로 기록한다.
