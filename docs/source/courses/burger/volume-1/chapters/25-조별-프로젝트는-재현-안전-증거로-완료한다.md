# 25. 조별 프로젝트는 재현·안전·증거로 완료한다

저장 지도에서 A·B·C 목표를 순찰하고 Cancel·STOP, 세 역할, 같은 조건 3회 재현을 하나의 완료 계약으로 묶는다.

## 학습 목표

- 준비·임무·안전·재현·포트폴리오 완료 계층을 구분한다.
- A→B→C terminal success와 Cancel 후 정지를 증거로 남긴다.
- 안전·운영 / Nav2·코드 / Evidence·QA 역할과 3개 RUN_ID를 연결한다.

## 선수 조건

- PART 1~6 Lesson 24까지의 Gate
- 실제 map·Localization·Nav2 또는 미실행 HOLD

## 핵심 개념

| 완료 계층 | PASS 기준 | 증거 |
| --- | --- | --- |
| 준비 | map·Localization·Nav2 Gate | RViz·TF·상태 log |
| 임무 | A→B→C terminal success | Goal·Feedback·Result |
| 안전 | Cancel 후 command·base 정지 | 담당자·영상·topic |
| 재현 | 같은 조건 3회 | RUN_ID 3개·결과표 |
| 포트폴리오 | 기준선·실패·수정·HOLD | diff·hash·인수인계 |

## 준비

- 현재 장비·shell·경로·ROS 배포판을 확인한다.
- 이 Lesson에서 필요한 실제 입력이 없으면 결과를 만들지 않고 `HOLD`로 남긴다.
- 명령과 관찰을 같은 실행 회차의 증거로 연결할 저장 위치를 준비한다.

## 실행

```bash
# 역할: 안전·운영 / Nav2·코드 / Evidence·QA
# A·B·C Goal은 같은 client를 좌표만 바꿔 순서대로 실행
ros2 action info /navigate_to_pose
ros2 topic info /cmd_vel --verbose
colcon test-result --verbose
```

## 예상 결과

:::{admonition} 예상 결과의 경계
:class: expected-result
아래 항목은 원문이 제시한 판정 기준이다. 실제 장비·설치본의 출력 로그를 이 문서가 대신 만들지는 않는다.
:::

- 같은 client로 A·B·C Goal을 순서대로 실행하는 계약을 세운다.
- terminal Result와 Cancel 후 command·base 정지를 별도로 확인한다.
- 같은 조건 3회 결과를 RUN_ID 3개로 묶는다.

## 관찰 포인트

- 프로젝트 완료 계약과 실제 simulator·실물 성공 증거를 구분한다.
- 역할 배정도 실제 팀 기록이 들어오기 전에는 HOLD다.

## PASS / HOLD / FAIL

::::{grid} 1 1 3 3
:gutter: 2
:class-container: status-gate-grid

:::{grid-item-card} ✓ PASS
:class-item: status-pass
준비·임무·안전·재현·인수인계가 모두 실제 증거로 연결된다.
:::

:::{grid-item-card} ◇ HOLD
:class-item: status-hold
simulator 3회·실물 3회·물리 STOP·팀 역할 배정은 실제 증거가 들어오기 전까지 HOLD다.
:::

:::{grid-item-card} ✕ FAIL
:class-item: status-fail
한 번의 Goal 전송 또는 RViz Path만으로 프로젝트 완료를 선언한다.
:::

::::

## STOP 조건

:::{danger}
Cancel은 물리 E-stop을 대신하지 않는다. 정지 담당과 전원 차단 수단이 없는 실물 시험은 진행하지 않는다.
:::

## 실패·문제해결

- Accepted를 terminal success로 기록
- Cancel request만 보고 command·base 정지 확인 생략
- 서로 다른 조건의 성공 3회를 재현으로 묶음

첫 수정 전에 **마지막 PASS와 첫 FAIL**을 기록하고 한 번에 한 변수만 바꾼다.

## 증거 체크리스트

- [ ] map·Localization·Nav2 Gate
- [ ] A·B·C Goal·Feedback·Result
- [ ] Cancel·STOP 담당자·영상·topic
- [ ] 동일 조건 RUN_ID 3개·diff·hash·인수인계

## 확인 문제

**질문:** 현재 문서만으로 simulator 3회와 실물 3회 성공을 PASS할 수 있는가?

:::{dropdown} 정답 확인
:class-container: knowledge-answer
아니다. 문서는 완료 계약만 잠그며 실제 실행 증거가 들어오기 전까지 해당 항목은 HOLD다.
:::

## 실습 과제

프로젝트 완료표를 만들고 현재 실제로 가진 증거만 PASS, 없는 실행은 HOLD로 표시한 뒤 다음 수집 순서를 정한다.
